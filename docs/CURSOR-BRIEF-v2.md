# Задание для Cursor: сторож сайта pconelab.co.il (v2, канон владельца учтён)

Копировать в Cursor целиком. Приложения, которые он должен получить вместе с этим текстом:
`docs/OWNER-CANON-20261104.md` (канон владельца, слова Романа) и `docs/canon.seed.json`
(тот же канон машинно, стартовое содержимое `sitewatch/canon.json`).
Полное ТЗ: `docs/sitewatch-spec-20261104.md` (разделы 4, 5, 7, 8, 11, 12 — обязательны).

---

## Роль и режим

Ты инженер. Делаешь **новый отдельный репозиторий** `pcone-sitewatch` — программу, которая проверяет
статический сайт мастерской и магазина PCone на поломки.

Границы, нарушать нельзя:

- работаешь только внутри нового репозитория; `/var/www/pconelab.co.il` и живой сайт — **только чтение**;
- `build.py`, генератор сайта, nginx, кроны сервера — **не твои**; ничего там не меняешь;
- никаких секретов, ключей, паролей и токенов в репозитории;
- никаких платных сервисов и внешних подписок;
- не выкладываешь ничего на живой сайт.

## Зачем это существует (приоритет при сомнении)

Сайт ломается после выкладок: возвращается старый заголовок, врут часы, цены попадают в meta, шапка шире экрана,
кэш отдаёт старый CSS. Цель: **ни одна поломка не доходит до клиента незамеченной**; механические чинит крон на
сервере, остальное уходит владельцу с доказательством.

Приоритет, когда правила конфликтуют:
1. никогда ложное «всё чисто»;
2. ноль ложных срабатываний на чистой копии;
3. скорость и стоимость прогона.

## Главное правило архитектуры: канон — данные, не код

Все факты (часы, телефон, адрес, почта, разрешённые цены, запрещённые фразы, гарантия, allowlist, severity)
лежат в `sitewatch/canon.json` и читаются правилом во время прогона. **Хардкодить эти факты в коде запрещено.**
`docs/canon.seed.json` — стартовое содержимое файла, скопируй его как есть; правки канона делает владелец,
а не программист. Если нужного факта в каноне нет — это вопрос в конце ответа, а не догадка в коде.

## Правила проверки v2 (каждое — отдельный модуль с тестом)

Разметочные (по HTML, работают в `preflight`):

- `HOURS_TEXT` — часы в видимом тексте не совпадают с каноном (все 5 языков);
- `HOURS_JSONLD` — `openingHours` в JSON-LD не совпадает с каноном или расходится с текстом страницы;
- `CONTACT` — телефон, адрес или почта отличаются от канона; чужой адрес вида `info@pconelab.io` — critical;
- `META_PRICE` — цена в `description` / `og:description` / `twitter:description`. Цен там нет вообще, включая
  товарные страницы AV. Единственное исключение — «диагностика 200 ₪», список исключений берётся из канона;
- `PRICE_FACT` — цена в теле текста противоречит списку разрешённых фактов канона (диагностика 200, плата 300,
  восстановление данных от 400, видеокарта 350–750, телефон после воды от 350, экраны только «от N ₪»).
  Противоречие — флаг, не автоправка;
- `BANNED_CLAIM` — запрещённые фразы из канона на любом языке: срочная/экспресс-диагностика, «в течение 4 часов»,
  «5000+ ремонтов» (замена — «с 2007 года»), скупка/трейд-ин б/у, «авторизованный сервис Apple»;
- `OLD_HEADER` — присутствует старый заголовок с синей полосой. Должна быть только шапка Arena. Это главная
  повторяющаяся поломка: правило обязано ловить её по структурному признаку, а не по тексту;
- `WARRANTY_RU` — текст гарантии Apple (ru) не совпадает с каноном дословно;
- `FREE_CLAIM` — «бесплатно» / free: **только сообщение**, никогда `safe_auto`;
- `ASSET_404` — ссылка на `css/`, `assets/`, `img/`, `js/`-файл, которого нет в дереве;
- `LINK_BROKEN` — внутренняя ссылка на несуществующий адрес;
- `LANG_404` — страница есть в одном языке и нет в другом при наличии `hreflang`;
- `HREFLANG` — набор альтернатив не совпадает с реально существующими страницами;
- `CACHE_BUST` — подключаемый `css/js` без версии (`?v=` или хеш в имени): из-за этого правка не видна;
- `JSONLD` — блок `application/ld+json` не парсится или пуст;
- `PAGE_4XX` — адрес отдаёт 4xx/5xx (в `nightly` по сети; в `preflight` — отсутствующий файл в локальном дереве).

Геометрическое (нужен браузер, только `nightly` и `preflight` по запросу):

- `MOBILE_OVERFLOW` — при ширине 390 px шапка или меню шире экрана (горизонтальная прокрутка). Проверяется
  headless-браузером на наборе ключевых страниц: главная каждого языка, услуги, товарная, статья.
  Если браузера в окружении нет — правило помечается `skipped` с причиной, **никогда** не «чисто».

## Severity (из канона, не менять)

- **critical**: неверные часы/телефон/почта, цена в meta, старый заголовок, запрещённая фраза, страница 4xx/5xx,
  шапка/меню шире экрана при 390 px;
- **high**: битый ресурс или ссылка, невалидный JSON-LD, несовпадение hreflang, отсутствующая языковая страница,
  отсутствующий cache-bust;
- **medium / info**: всё остальное.

## Пять режимов

- `fast` (≤60 с, ≤200 адресов): разметочные правила на ключевых страницах всех языков;
- `nightly` (полный, до 30 мин): все правила, включая внешние ссылки и геометрию;
- `preflight` (≤60 с): разметочные правила **по локальной копии дерева до выкладки**;
  `pcone-sitewatch preflight --root <путь> --base https://pconelab.co.il`, код 1 = выкладка запрещена;
- `verify`: сравнение «до/после» по указанным страницам, код 2 и строка `reverted: <файл> <причина>`
  при ухудшении (откат делает сервер: программа к чужому дереву только на чтение);
- `watch-silence`: нет коммита 26 ч → код 1 и строка `сторож молчит: последний прогон <дата>`.

## Повтор = шаблон

`state.json` хранит историю по `rule_id`: `first_seen`, `last_seen`, `fixed_at`, `recurrence`.
`recurrence ≥ 2` → `"repeat": true`, `shared_file`, `shared_count`. Если тот же `rule_id` + тот же фрагмент
встречается на ≥3 адресах — ищем общий источник (include, общий CSS/JS, место в генераторе). В `report.html`
отдельный блок «Повторяется: искать в шаблоне».

## allowlist

`sitewatch/allowlist.txt`, строка: `rule_id | url | причина | кто, дата`. Только свой `rule_id` и свой адрес,
`*` запрещён, без причины строка игнорируется. Скрытое видно в отчёте как `скрыто по allowlist: N`.
Стартовые записи — из канона (`allowlist_seed`):

- `OLD_HEADER` на `/gta6/article-regional-versions*` — старый заголовок оставлен решением владельца 04.11;
- ссылка «Б/у техника» в подвале — не дефект (решение 27.10);
- `/gta-rp/*` (5 языков) — не редактируются никогда: находки только `info`, `safe_auto` запрещён.

Исключения старше 60 дней раз в неделю показываются списком «проверить, ещё задумано?».

## Отчёт

- `findings.jsonl` — `id, rule_id, severity, url, evidence, found_at, recurrence, repeat, shared_file,
  allowlist (bool), action (report_only|safe_auto|skipped)`;
- `state.json`, `report.html` (открывается на телефоне: сколько найдено, что критично, адрес, доказательство,
  блок «Повторяется», строка `скрыто по allowlist: N`), `ALERT.md` (только экстренное);
- `digest` — **одна строка до 140 знаков**: `Сторож: всё чисто (проверено 812) — <ссылка>` /
  `Сторож: 3 новых, 1 критичная (часы на ru/) — <ссылка>` / `Сторож: прогон не прошёл — <причина>`.

## Не делать в v1

- автоправки вообще: v2 сдаётся как обнаружитель. Автопочинка и её перепроверка с откатом — следующий этап
  (раздел 5 ТЗ), после приёмки правил;
- магазин Woo, карточки, цены, остатки;
- скорость загрузки (Core Web Vitals) и Google (отзывы, позиции);
- сервер: nginx, диск, бэкапы — зона Тима;
- проверка цен против мастер-прайса — отдельный контур.

## Тесты — часть сдачи

- фикстура на каждое правило (≥15 поломок), `tests/expected.json` перечисляет их;
- `pytest -q` зелёный;
- `preflight` на фикстуре → код 1 и точное совпадение с `expected.json`; на исправленной копии → код 0 и ноль
  находок (ложных срабатываний быть не должно);
- `verify` на искусственном ухудшении → код 2 и строка `reverted:`;
- `watch-silence` со старым `state.json` → код 1;
- `allowlist` без причины → находка осталась; с причиной → `скрыто по allowlist: 1`;
- `MOBILE_OVERFLOW` без браузера → `skipped`, а не «чисто»;
- правка канона (например, часы) меняет результат прогона без правки кода — доказательство, что факты не
  захардкожены.

## Формат ответа

1. Ссылка на репозиторий/ветку или архив — первым пунктом.
2. Вывод `pytest -q` целиком.
3. Вывод `preflight` на фикстуре с поломками и на исправленной.
4. Таблица: правило → что ловит → доказательство → тест.
5. `canon.json`: какие ключи прочитаны, где остались заглушки.
6. Что решил сам + список `ТРЕБУЕТ РЕШЕНИЯ ЗАКАЗЧИКА: <вопрос>`.
7. Затраченное время и что осталось за границей v1.

**ЖДУ ПОЛНЫЙ ПАКЕТ.** Частичная выдача («правила готовы, тесты позже») не принимается: приёмка по разделу 8
ТЗ и по канону, без тестов пакет считается несданным.

## Жёсткие правила

- не выдумывать адреса, правила, цены и формулировки: нет в каноне — вопрос в конце;
- не менять живой сайт, `build.py`, nginx, кроны, не «улучшать» тексты сайта;
- каждое правило — с положительным контролем (нашло) и отрицательным (молчит на исправленном);
- «так задумано» решается только allowlist-записью с причиной и датой;
- отчёт — файлом на диске первым действием, а не телом ответа;
- Python 3.11, без платных зависимостей, без секретов.
